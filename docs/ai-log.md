# AI協作日誌

每週記錄 3 到 5 筆。最有價值的紀錄是「AI的產出不符合使用者需求，你發現並修正」的經驗。第三週發表時，會從這裡挑一個例子說明。

## 第一週

### 1. 整理需求、痛點與矛盾，建立醫師人物誌與任務流程

- **我的提示**
  - 請閱讀專案中的案例資料，依使用者角色（報告醫師、放射師、超音波技術員）整理需求與現行系統的痛點。
  - 接著列出受訪者之間說法不一致、同一受訪者前後說法改變、描述不清需要再確認的地方，並註明出處。只列出問題，不要替我決定怎麼處理。
  - 依訪談為報告醫師建立人物誌草稿，推測的部分明確標示；並用 Mermaid 畫出從開啟工作清單到完成報告的任務流程，標出痛點。
- **AI 的產出（摘要）**
  - 依三種角色列出需求表與痛點，痛點區分「明確陳述」與「由需求反推」。
  - 列出 5 項受訪者間不一致、6 項醫師前後說法改變、18 項待確認事項，皆註明出處，例如「一-2 #7」。
  - 人物誌中沒有依據的內容標為【推測】；流程圖以實線、虛線框區分兩種痛點。
- **我的判斷或修正**
  - AI 依要求只列問題、沒有替我決定處理方式，並主動說明訪談記錄是摘要筆記，所以人物誌的「代表性說法」是改寫，不是原話。
  - 流程圖的步驟大多是由需求反推的現行流程，不是訪談直接描述，需要再向受訪者確認。
  - 檢查出處後直接採用，未修改。

### 2. 製作醫師工作清單與打報告畫面的互動雛型

- **我的提示**：請依我整理的需求，用案例資料中的模擬資料製作單頁 HTML 互動雛型，包含醫師工作清單與打報告畫面。
  - 工作清單上方要明顯顯示未完成報告的分項數量。
  - 點選一筆檢查後進入打報告畫面，畫面一側是影像示意區，另一側依檢查類別顯示範本欄位。
  - 儲存後要自動跳到下一筆未完成的報告。
- **AI 的產出（摘要）**
  - 產出單一 HTML 檔，並以瀏覽器自動測試確認「儲存後跳下一筆」可以運作。
  - AI 自行做了 7 項訪談沒有定論的決定，並在回覆中逐條列出，例如：
    - 已 DC 醫令採放射師的處理方式
    - 「下一筆未完成」依清單排序與篩選決定
    - 儲存為「已完成」、認證為「已認證」並鎖定
- **我的判斷或修正**
  - 雛型必須先做出某種選擇才能運作，所以 AI 先做決定可以接受；重要的是它把每項決定都列出來，讓我能逐一檢查。
  - 這些決定後來在 README 中標為【暫定】，需要我逐項確認後才算我的設計決定。
  - 檢查出處後直接採用，未修改。

### 3. 盤點視覺不一致，建立迷你設計系統

- **我的提示**
  - 請檢視我目前的雛型，整理出畫面中實際用到的顏色、字級、間距與元件，並指出不一致的地方。
  - 接著以 tokens.css 起始範本為基礎，協助我整理成一份迷你設計系統。
  - 報告狀態的語意色請提供兩到三組選項，說明各自在色彩對比與色覺辨識上的考量，由我決定。
- **AI 的產出（摘要）**
  - 盤點出 30 個寫死的色值、11 種字級、約 19 種間距值，以及 18 項不一致。例如：
    - 「返回工作清單」在兩處使用不同按鈕樣式
    - 「已完成」列底色與選取底色無法區分
    - 紅色同時代表「醫令已DC」與錯誤訊息
  - 狀態色提供 A、B、C 三組，以 WCAG 對比與色覺模擬的色差（ΔE）比較，並做了一頁色覺模擬對照。
  - 沒有替我選擇。
- **我的判斷或修正**
  - 選擇 B 組：以國際通用的色覺友善色盤（Okabe-Ito）為基礎調深，改用橘、天藍、藍綠、洋紅紅。
  - AI 也指出，三組的列底色對比都只有 1.1 到 1.2:1，所以狀態一律要以「圖示＋文字」標示，顏色只做輔助。
